P3 · Spring Boot + Thymeleaf

URLs, navegación y errores

Pulsa los botones para observar cómo Thymeleaf construye enlaces con th:href, cómo Spring recibe parámetros y cómo se muestran páginas de error sin base de datos ni clases de dominio.

01 · Enlace interno sencillo

Ir a otra ruta

th:href="@{/saludo}" genera una URL relativa a la aplicación. Es preferible a escribir una ruta fija en el HTML.

02 · Parámetro de consulta

Pasar datos en la query string

@{/saludo(nombre='Lucía')} construye /saludo?nombre=Lucía. El controlador lo recibe con @RequestParam.

Saludar a Lucía Saludar a Ada Lovelace
03 · Variable de ruta

Un valor que forma parte de la ruta

@{/alumnos/{id}(id=${idEjemplo})} genera /alumnos/42. El controlador lo recibe con @PathVariable; no oculta el identificador.

04 · Enlace externo

Navegar fuera de la aplicación

Las URLs externas pueden escribirse con th:href o como un href HTML normal. target abre otra pestaña.

05 · Errores HTTP

Probar páginas personalizadas

Cada botón provoca intencionadamente un estado HTTP de error. Spring Boot busca plantillas específicas como error/404.html y plantillas generales por familia, como error/4xx.html y error/5xx.html.

Probar error 400 Probar error 403 Probar error 404 Probar error 500 Probar ruta inexistente

Las rutas 400 y 403 usan la plantilla general 4xx; la 404 tiene una plantilla propia; la 500 usa la plantilla general 5xx.

Idea clave: ${...} lee datos del modelo; @{...} construye URLs. Para parámetros sensibles no basta con cambiar GET por POST: protege el transporte con HTTPS y valida siempre en el servidor.
